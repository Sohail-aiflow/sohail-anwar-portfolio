### Verified local root causes and implementation

F-A01 combined the document's existing `scroll-padding-top`, section anchor margin, and large section padding. Native fragment scrolling aligned the padded section edge, leaving its actual title much lower. A new responsive `--section-anchor-clearance` token (5.5rem above the mobile breakpoint, 1.5rem below it) lets each homepage section's scroll margin account for both the existing anchor offset and its section padding. Connect also has a viewport-based minimum height so the browser can reach that destination before hitting the document's maximum scroll position. No text or section padding was shortened to create the alignment.

A focused keyboard test additionally reproduced Next's same-hash navigation behavior: after moving down to selected project details, activating Work again could leave the viewport there. The primary navigation now explicitly scrolls the requested section when its hash is already current, honors reduced motion, preserves modified-link behavior, and retains section focus. This is part of the approved navbar fix, not a change to unrelated homepage links. The failed run is retained as evidence; the corrected keyboard test subsequently passed in 10.2 seconds (`focused-keyboard-retest.log`).

F-A02's native radio selector updated the preview but had no explicit mobile reveal step. Deliberate label activation and mobile Space/Enter activation now schedule the selected visible details into view at widths below 768px. Space/Enter also focus the preview title with `preventScroll`; normal Tab/arrow radio navigation stays in the selector. Reduced-motion users receive an immediate reveal. Desktop/tablet selection, native no-JavaScript selection, and genuine case-study links remain available. Re-activating the already selected project also reveals it.

F-A03 removes only the two standalone arrows named above and their now-unused imports/CSS. Project-selector arrows communicate the working selection interaction; arrows inside case-study links, CTA links, and other genuine navigation controls remain. This is an interaction audit, not a blanket removal of the site's icon style.
